## [Unreleased]

### Added
- **Case Study**: `docs/case-study/` records how the project was scoped and built, the ten defects that looked fine until checked, how each layer of verification works and what it does not cover, the licensing evidence, and how work was divided between the owner and an AI coding agent. It also records that the nine release runtime tests were skipped in CI, which built no release environment, until the job below.
- **Release Runtime Tests In CI**: the nine tests in `tests/test_release_packaging.py` skipped on every CI run, because CI never built the isolated `text` and `pdf` release environments. A `release-runtime` job now builds both from the pinned requirement files, with no test dependency installed, runs the tests from them, and fails if any skips. The lock files' hashes name macOS arm64 wheels, so the job installs the same versions as Linux wheels: it checks the pinned versions, not the exact macOS artifacts.
- **Case Study In Traditional And Simplified Chinese**: every chapter of `docs/case-study/` is available as `.zh-TW.md` and `.zh-CN.md` beside the English, with a language switcher at the top of each, as the READMEs have. The Simplified Chinese uses mainland terminology rather than a character conversion of the Traditional. The three READMEs link to the case study in their own language.
- **Plain Text And Docling JSON From The Web Page**: the README listed Markdown, HTML, Docling JSON and plain text, while the page offered only the first two. Every release now offers plain text. Docling JSON is offered where an engine produces it: the `pdf` release yields it for PDFs and says why a Markdown or text input has none, and the `text` release, which runs no engine, does not offer it at all. Each format is served with its own media type, and `--diagnostics` reports the outputs a frozen candidate can produce beside its inputs.
- **Downloads Named After Their Document**: a single conversion downloaded as `converted-document.md` and a batch as `document-1.md` to `document-5.md`, whatever was uploaded. The download is now named after the upload's last path segment, sanitized so it can neither traverse a path nor break out of the header, made distinct within an archive, and carried as RFC 6266 percent-encoded UTF-8 so a Chinese file name survives. The file on disk still never uses the uploaded name.
- **Model-Free PDF Engine (`docling-native`)**: PDF conversion through Docling's `NativePdfPipeline`, which runs no layout, table or OCR model, so PDFs convert without PyTorch or downloaded model weights. `auto` places it after the model-based engines, and every conversion records its reduced fidelity as a warning (`document_converter/engines/docling_native_engine.py`).
- **`--strip-page-numbers`**: Opt-in removal of lines holding only digits during `--clean`.
- **macOS `pdf` Release Profile**: the packaged local app can accept text-layer PDFs. `scripts/packaging/profiles.py` declares the reviewed profiles, `bootstrap_macos.sh` takes `RELEASE_PROFILE=pdf`, the launcher reads its profile from the frozen bundle, and `requirements-macos-arm64-pdf.lock` pins 60 hash-locked wheels with no PyTorch, no optional engines and no model weights. A scanned PDF is reported as having no text layer instead of returning an empty document. The reviewed `text` profile is unchanged.
- **`audit_notices.py`**: checks that every wheel a profile pins carries its own license notice, reading each released wheel named by the lock file's hash without installing it, so a dependency bump can be verified from any machine with network access rather than only on the target Mac (`scripts/packaging/audit_notices.py`).
- **macOS VM Verification SOP**: `docs-release/macos-vm-verification.md` walks a candidate through a clean macOS guest - the two risks that only appear on someone else's machine. It transfers the ZIP by HTTP so the quarantine attribute is really applied and Gatekeeper really blocks, then runs `--diagnostics` on a guest with no Python to prove the app is self-contained. States what it does not cover: chip generations and macOS major versions. Needs no second Mac and no paid account; Apple's licence allows two macOS VMs per Apple Silicon host.
- **Shared Synthetic PDF Builders**: `tests/pdf_samples.py` writes structurally valid PDFs (correct cross-reference offsets, font resource, real content stream) so the suite needs no committed PDF fixture.

### Fixed
- **Text Release Loaded Engine Code And Refused To Start**: routing the web page's Markdown and text through `TextDirectEngine`, and an unused top-level `EngineError` import, made the `text` release import `document_converter.engines`, whose `__init__` loads every adapter. The frozen launcher's boundary check then refused to start (`Unexpected release modules`), and the release runtime CI job had been red on `main` since. The release path reads UTF-8 directly again, without importing the package, and the unused import is gone; from-source conversion still goes through `TextDirectEngine`. A test now runs the text release's conversions in a fresh interpreter and asserts none of its forbidden modules loads, so the main test job catches this too.
- **MinerU Adapter Could Never Succeed, And Its Extra Installed The Wrong Package**: the adapter ran `mineru kit parse`, but MinerU 4.x's `mineru` command has no `kit` subcommand, so every MinerU conversion failed before its `mineru-kit` fallback was reached. It now runs `mineru-kit parse INPUT -o OUTPUT --tier standard`, as read from the 4.0.12 wheel, with no remote-service option, and never the `mineru` command, which prepares usage telemetry for mineru.net on every subcommand. `list-engines` detects MinerU by `mineru-kit`, names the install command, and keeps each row on one line, since a wrapped install command read as two. The `mineru` extra installed `magic-pdf`, the older AGPL-3.0 package with no `mineru-kit`; it now installs `mineru>=4,<5`. The READMEs, `docs/LICENSE_AUDIT.md` and `THIRD_PARTY_NOTICES.md` say so, including the telemetry and model downloads that come with installing MinerU. MinerU remains outside both release profiles.
- **Engine Failures Named For What The User Can Do**: a from-source install without Word support answered a `.docx` upload with the engine chain's English text, naming the server's generated temporary file. When every engine fails for want of a package, the page now says in Chinese which upload and which Python module, with the install command where the engine gives one; any other failure keeps its reason but names the upload instead of the temporary file. The engine chain's error keeps each engine's exception (`EngineError.failures`), so the page asks why each failed instead of parsing text, and a broken file is never blamed on a missing package. The check reads that attribute rather than importing engine code, which the `text` release does not freeze.
- **UAT Reproducible From The Repository Root**: `verification/2026-10-13-uat/uat.py` looked for its samples in the working directory while `make_samples.py` wrote them beside itself, so the documented commands failed. Both now use the script's folder; `verification/*/samples/` is ignored, since the PNG sample was not covered by `*.pdf`; and `uat-after.txt` is regenerated, showing the size limits in both units as the page now states them.
- **Size Limits Were Stated In A Unit Most Readers Do Not Know**: the page and its messages said "24 MiB" only, and its size display divided by 1,048,576 while labelling the result "MB" - so a file Finder lists as 25.2 MB appeared on the page as 24.0 MB. Every limit now states both units, derived from the one byte constant so they cannot drift (`24 MiB（約 25 MB）`), and the page shows sizes in decimal, as Finder does.
- **An Empty Conversion Returned An Empty File**: a PDF that is a scan or a single picture, and an empty text file, were answered with 200 and a file holding a lone `<!-- image -->` placeholder or nothing at all. The guard that was meant to prevent this ran only in the `pdf` release and recognised only one engine's warning. It now asks the result itself whether any text was recovered - `ConversionResult.has_recovered_text()` - so it holds for every release and every engine, and the reason names only causes that release could have.
- **Rejection Messages Were Half In English And Named Nothing**: an unsupported file was refused with `Unsupported input type` on a Traditional Chinese page, without saying what would work; the size, count and output-format limits, the cross-origin and busy responses and the conversion failure were English too. Every message is now in the interface's language, an unsupported input names the formats this release accepts, and a request with no file is answered in plain language instead of with FastAPI's own validation structure.
- **A Non-UTF-8 Text File Reported A Python Codec Error**: a Big5, GBK or UTF-16 `.txt` produced `'utf-8' codec can't decode byte 0xff…`. It now names the likely encodings and asks for a re-save as UTF-8.
- **HTML Entities In Markdown And Plain Text**: Docling's Markdown serializer HTML-escapes a document's own text, so a PDF reading "Inbound & Outbound" was written out as "Inbound &amp; Outbound", and `<` and `>` likewise. Both Docling adapters now undo exactly one level of that escaping; their HTML output, where the entities belong, is unchanged.
- **Plain Text From A Markdown Input Kept Its Markdown**: the direct text path set a Markdown file's raw source as its plain text, so `--to txt` on a `.md` returned heading marks and bullets. Markdown is now rendered, and a `.txt` input is returned untouched.
- **Release Notices Were Collected By File Name Only**: the packaging step matched notice files by name, so it silently dropped every notice a wheel ships under the standardised `<dist-info>/licenses/` location with an upstream name, and refused the build outright for a wheel that ships nothing else. The `pdf` profile lost 21 notice files that way, including the 18 covering PDFium's bundled components (`abseil`, `freetype`, `icu`, `libjpeg-turbo`, `libpng`, `zlib` and more) that `pypdfium2` ships, and `tqdm`'s `LICENCE`. Notices are now recognised by name - including the British spelling - and by that standard location (`scripts/packaging/collect_notices.py`). The reviewed `text` profile's collected set is unchanged.
- **`latex2mathml` Pinned To A Release That Ships No License**: 3.81.0 and 3.81.1 omit the license file from both the wheel and the sdist, so the `pdf` build had no notice to collect for a dependency it redistributes. The profile pins 3.80.0, the last release that ships it, which still satisfies `docling-core`'s `>=3.77.0,<4.0.0`.
- **Markdown Cleaner Data Loss**: `--clean` deleted any line holding only 1-4 digits, which removed table values such as a quantity or a year. Those lines are now preserved; labelled page markers (`Page 3 of 12`, `4 / 20`, `- 5 -`) are still removed.
- **Test Suite Could Not Pass From A Fresh Clone**: three CLI and watcher tests required `tests/fixtures/sample_text.pdf`, which `.gitignore`'s `*.pdf` rule keeps out of the repository. They now build their input in a temporary directory.
- **PDF Detection Varied With The Environment**: the built-in stream analyzer classified ordinary text PDFs as `scanned` because it required an end-of-line before `endstream` and decoded only Flate streams. It now tolerates the missing EOL and decodes ASCII85, including ASCII85 wrapping Flate, and `pypdf` is a declared dependency so detection no longer depends on what happens to be installed.
- **Misleading Scanned-PDF Warning**: the pipeline claimed "OCR processing applied" for every scanned PDF, including engines that run no OCR. The warning now names the engine and tells the reader to check the output.
- **Secret Scan Never Ran On A Push**: the TruffleHog step passed the default branch as `base` and `HEAD` as `head`, which are the same commit on a push to `main`, so it stopped with "BASE and HEAD commits are the same" before scanning. It now scans the commits each event adds: a pull request's base against its head, or the range a push advanced.

### Changed
- **Tests Use httpx2 Where Starlette Asks For It**: Starlette 1.x runs its `TestClient` on `httpx2` and warns, deprecating plain `httpx`. The `dev` extra adds `httpx2` (BSD-3-Clause, development only) and keeps `httpx` for older Starlette within the supported FastAPI range.
- `clean_markdown`, `write_result`, `process_batch` and `DirectoryWatcher` accept `strip_bare_numbers`.
- `AGENTS.md` validation now runs `document-converter list-engines`; `--list-engines` was never a registered option.

### Removed
- **Python 3.10 Support**: `requires-python` is now `>=3.11,<3.15` and the CI matrix tests 3.11 and 3.12. `tests/test_security_baseline.py` imports `tomllib`, which entered the standard library in 3.11, so the suite has never been collectable on 3.10 and the job aborted before any test ran. The README already recommended 3.11 or 3.12.

## [0.2.0] - 2026-10-08

### Added
- **OpenSpec Driven Architecture**: Introduced canonical `openspec/specs/` baseline specifications for CLI interface, engine adapters, output serialization, security, and PDF text-layer detection.
- **PDF Text-Layer vs Scanned Auto-Detection**: Zero-dependency built-in PDF stream analyzer and metadata profiling (`document_converter.detector`).
- **Markdown Cleaner**: `--clean` mode with fenced code block and LaTeX math formula preservation, excessive whitespace compression, and page number noise elimination (`document_converter.cleaner`).
- **Layout Preservation**: `--preserve-layout` flag to maintain exact page break spacing.
- **CLI Inspect Subcommand**: `document-converter inspect` to quickly diagnose PDF text layer presence and classification.
- **Test Fixtures & TDD Suite**: Synthesized `sample_text.pdf`, `sample_scanned.pdf`, and full test suite covering CLI, cleaner, pipeline, detector, writer, and security baseline.
- **CI Pipelines**: Matrix testing pipeline (`.github/workflows/test.yml`) with code coverage alongside existing security audit.

### Security & Licensing
- Strictly isolated `marker` (GPL-3.0) and `mineru` (AGPL-3.0 / CC-BY-NC) into `optional-dependencies`.
- Documented third-party code & model licenses in `THIRD_PARTY_NOTICES.md` and `docs/LICENSE_AUDIT.md`.
- Established strict `.gitignore` data leak prevention for credentials, documents, and model checkpoints.

## [0.1.0] - 2026-10-08
- Initial architecture with Docling primary engine, Typer CLI, and multi-format output writer.
