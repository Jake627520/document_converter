# 1. 問題與範圍

[English](01-problem-and-scope.md) | **繁體中文** | [简体中文](01-problem-and-scope.zh-CN.md)

## 問題

處理規格書、內部備忘錄和審查文件的人，常常想把它們轉成 Markdown 或純文字——
放進知識庫、wiki，或交給 AI 助理。這些文件往往是機密。把它們上傳到線上轉檔網站，
正是最不該做的事。

所以需求說起來簡單，做起來容易出錯：**在使用者自己的電腦上轉換，文件絕不送到任何地方。**

## 為誰而做

| 使用者 | 需要 | 因此排除了什麼 |
| --- | --- | --- |
| 手上有機密文件的人 | 什麼都不離開這台電腦 | 任何雲端 API、任何遙測、任何沒事先說明就在執行時下載的模型 |
| 不懂技術的同事 | 雙擊就能用 | 「請先安裝 Python 3.12，然後……」 |
| 開發者 | 從原始碼執行、寫腳本呼叫 | 沒有 CLI 的封閉執行檔 |

於是有了一個核心、三種入口：命令列、只在 `127.0.0.1` 上提供的瀏覽器工作台，以及打包好的 macOS App。

## 為什麼不直接用 MarkItDown？

Microsoft 的 [MarkItDown](https://github.com/microsoft/markitdown) 免費、MIT 授權，
使用非常廣泛。單論轉換品質，沒有贏過它的可能。

但它自己的貢獻指南把**桌面與網頁應用程式列為範圍之外**。它是函式庫加 CLI。
它留下的空缺，正是這個專案瞄準的地方：一個從沒打開過終端機的人也能用的東西，
而且它對自己說的每一句話都經過查證。

這裡的引擎選了 Docling，原因很明確：它有一個 `NativePdfPipeline`，
可以讀出 PDF 本來就有的文字，**完全不載入任何 AI 模型**。下一個決定因此才可能成立。

## 定義了發行版 App 的決定：不用 PyTorch

Docling 預設的 PDF 流程會跑版面與表格模型。這些模型需要 PyTorch——安裝起來好幾 GB——
而且第一次執行時會下載模型權重。

對一個給機密文件用、雙擊就開的 App 來說，兩者都不對：App 會變得非常龐大，
而「第一次使用時下載權重」是一個使用者沒有要求的網路連線。所以負責人的決定是
**完全不用 PyTorch**，建立在不需模型的讀取器上。代價是真實的，而且在每個相關的地方都寫明了：
不重建標題層級、不輸出 Markdown 表格、沒有 OCR。

## 兩種發行設定檔，各有明確邊界

不是一個什麼功能都有的 App，而是兩種經過審查的設定檔：

| 設定檔 | 接受 | 內含 | 存在的理由 |
| --- | --- | --- | --- |
| `text` | `.md` `.markdown` `.txt` | **完全不含文件引擎** | 最小但有用的版本——程式碼最少，要負責的授權也最少 |
| `pdf` | 以上全部，加上有文字層的 PDF | Docling 的免模型讀取器與 PDFium | 大家手上實際有的就是 PDF |

設定檔不是使用者能切換的選項，而是在 App 建置時強制執行：建置時拒絕凍結任何列在該設定檔禁用清單上的模組，
凍結後的 App 啟動時也會回報沒有載入任何一個。[第 2 章](02-architecture.zh-TW.md)說明怎麼做到。

## 刻意不做的事

| 不做 | 原因 |
| --- | --- |
| 掃描 PDF 的 **OCR** | 每一種 OCR 選項，不是要下載模型，就是授權附帶條件。掃描檔會被回報為沒有文字層——絕不靠猜 |
| App 支援 Office 文件與圖片 | 它們需要模型流程，而這個 App 的範圍正是要避開它 |
| **Apple 公證（notarization）** | 需要付費的 Apple Developer 帳號（每年 USD 99）。在 App 有負責人圈子以外的使用者之前，這筆費用不划算；[`docs-release/macos-vm-verification.md`](../../docs-release/macos-vm-verification.md) 說明不靠它也能在乾淨機器上測試 |
| Windows | 沒有安裝檔、沒有測試——文件也照實這麼寫，不讓人誤以為有 |

每一項排除，都寫在使用者會去找那個功能的地方。有寫進文件的缺少功能是一個決定；
沒寫進文件的，就是一份遲早會來的錯誤回報。
