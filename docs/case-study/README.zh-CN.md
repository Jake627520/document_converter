# 案例研究：把开源引擎做成可以交付的产品

[English](README.md) | [繁體中文](README.zh-TW.md) | **简体中文**

这个项目在用户自己的电脑上，把文档转换为 Markdown、HTML、纯文本和 Docling JSON。
转换引擎并不是重点——它是 [Docling](https://github.com/docling-project/docling)，
采用 MIT 许可证，任何人都可以免费使用。这份案例研究讲的是两者之间的一切：从“引擎在我电脑上能跑”，
到“同事双击就能用，而且它对自己说的每一句话都是真的”。

## 塑造了整个项目的发现

有十次，东西看起来没问题，实际上有问题。

密钥扫描每次推送都报告成功，却一个提交都没读。许可声明收集器报告成功，
却悄悄漏掉了 21 份声明。网页返回“200 OK”，给的是一个 97 字节、什么内容都没有的文件。
清理功能把表格里的数字 `84` 删掉了，还报告转换干净无误。

这些都没有显示为失败。每一个都是对一项“已通过”的检查问了同一个问题才找到的：
**它实际上看了多少？**——[第 3 章](03-silent-failures.zh-CN.md)逐一说明。

## 是怎么做出来的

代码由 AI 编程智能体（Claude Code）编写。产品决策、范围、许可与公开的风险判断，
以及在真实硬件上用真实文档做的验收，都由项目负责人负责。
[第 6 章](06-working-with-an-ai-agent.zh-CN.md)会具体说明哪些是谁做的，包括智能体做错的地方。

这里的每一项说法，都链接到支持它的 PR、提交或报告。
