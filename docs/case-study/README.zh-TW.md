# 案例研究：把開源引擎做成可以交出去的產品

[English](README.md) | **繁體中文** | [简体中文](README.zh-CN.md)

這個專案在使用者自己的電腦上，把文件轉成 Markdown、HTML、純文字和 Docling JSON。
轉換引擎不是重點——它是 [Docling](https://github.com/docling-project/docling)，
MIT 授權，任何人都能免費使用。這份案例研究談的是兩者之間的一切：從「引擎在我電腦上能跑」，
到「同事雙擊就能用，而且它對自己說的每一句話都是真的」。

## 塑造整個專案的發現

有十次，東西看起來沒問題，其實有問題。

密鑰掃描每次推送都回報成功，卻一個 commit 也沒讀。授權聲明收集器回報成功，
卻默默漏掉了 21 份聲明。網頁回傳「200 OK」，給的是一個 97 bytes、什麼內容都沒有的檔案。
清理功能把表格裡的數字 `84` 刪掉了，還回報轉換乾淨無誤。

這些都沒有顯示成失敗。每一個都是對一項「已通過」的檢查問了同一個問題才找到的：
**它實際上看了多少？**——[第 3 章](03-silent-failures.zh-TW.md)逐一說明。

## 怎麼做出來的

程式碼由 AI 程式代理（Claude Code）撰寫。產品決策、範圍、授權與公開的風險判斷，
以及在真實硬體上用真實文件做的驗收，都由專案負責人負責。
[第 6 章](06-working-with-an-ai-agent.zh-TW.md)會具體說明哪些是誰做的，包括代理做錯的地方。

這裡的每一項說法，都連結到支持它的 PR、commit 或報告。
